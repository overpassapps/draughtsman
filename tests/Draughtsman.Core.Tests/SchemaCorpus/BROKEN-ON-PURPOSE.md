The first row was caught on 2026-10-01 by a ratio of two timings (four times the members took 13.3 times as long, limit 8). That test was replaced on 2026-10-02 by the counts above because the ratio flaked for linear code (8.0x on the Windows runner; over 8x in 4 to 6 of 30 single-shot pairs on this Mac and on the Windows VM with other threads allocating in the process): garbage collection is not proportional to the work.

The stream test (`Validating_a_stream_of_ten_thousand_small_documents_stays_fast`) was a median of 8.1 s against 2.5 s times the load scale on the Windows runner on 2026-10-07 for unchanged code (a third failure after a loaded Mac and an earlier Windows run), so on 2026-10-07 it was replaced by a count of the bytes allocated (identical on every host, 3,712 a document, 4.00x for 4x the documents):
